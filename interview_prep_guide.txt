============================================================
TRIP SPARK - INTERVIEW PREPARATION GUIDE
============================================================

Below are the likely questions an interviewer will ask, categorized by topic, along with "Pro" answers that highlight your technical depth.

------------------------------------------------------------
1. ARCHITECTURE & SECURITY
------------------------------------------------------------
Q: Why did you build a Node.js backend instead of calling the Google/Gemini APIs directly from the frontend?
A: "Security and control. If I call Google APIs from the frontend, my API key is exposed in the network tab for anyone to steal. By using a backend proxy, the API key stays safe on the server. Also, it allowed me to implement a caching layer to reduce costs and latency."

Q: Explain your 'Proxy Pattern' for images.
A: "Instead of the frontend requesting images directly from Google, it requests them from my server. My server fetches the image, caches the metadata, and returns it. This prevents CORS issues and gives me a central place to manage image quality."

------------------------------------------------------------
2. DATA & PERFORMANCE
------------------------------------------------------------
Q: I see you have a 'HotelCache' in your Prisma schema. Why?
A: "Google Places API is expensive and has rate limits. By caching hotel details (name, coordinates, photos) in my PostgreSQL database, I only hit the API once for each location. Subsequent users get the data instantly from my DB, which is 10x faster and 100% cheaper."

Q: How do you handle the coordinates for the map path?
A: "The AI provides the city name, but not always the exact latitude/longitude. I wrote a synchronization service that takes the AI's suggestions, looks them up in the Google Geocoding API, and then updates the map markers asynchronously."

------------------------------------------------------------
3. REACT & UI/UX
------------------------------------------------------------
Q: How do you pass data from the 'Trending Destinations' grid back up to the search bar?
A: "I used the 'Lifting State Up' pattern. The main state lives in App.tsx. I passed a selection function down to the grid component as a prop. When a user clicks a destination, it updates the parent state, which automatically pre-fills the search form at the top."

Q: Why did you use Framer Motion for animations?
A: "To improve the perceived performance. Using staggered reveals and 'whileInView' triggers makes the app feel premium and 'alive' without sacrificing actual load speed. It creates a better emotional connection for the user."

------------------------------------------------------------
4. THE "AI" LOGIC (GEMINI)
------------------------------------------------------------
Q: How do you ensure the AI returns data in a format the app can understand (JSON)?
A: "I used 'Prompt Engineering' and System Instructions. I explicitly told the model to respond ONLY in a specific JSON schema. On the backend, I implemented a parser that validates the JSON before sending it to the frontend to prevent crashes."

Q: What happens if the AI fails or returns bad data?
A: "I implemented error boundaries and fallback states. If the AI response is malformed, the backend catches the error and the frontend shows a user-friendly 'Try Again' state instead of just breaking."

------------------------------------------------------------
5. CHALLENGES & GROWTH
------------------------------------------------------------
Q: What was the hardest part of this project?
A: "Syncing three different data sources: The AI's creative itinerary, Google's geospatial data, and my local database. Ensuring that a marker on the map actually matched the hotel the AI recommended required a lot of logic around string matching and location ID verification."

Q: If you had more time (V2), what would you add?
A: "I would implement 'Social Sync' where users can share their generated trips to a community feed (Pinterest-style), and add real-time flight price integration to make it a true 360-degree travel tool."
